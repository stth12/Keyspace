# Implementation decisions

1. NestJS 12 replaces planned 11 after npm audit flagged the older Express/multer dependency chain. Prisma stays on stable 7.10 rather than 8 RC. Overrides pin fixed deepmerge-ts/mysql2 versions; compatibility is verified by migrate/generate/tests.
2. Confidential server envelopes use a fresh random DEK per message, ChaCha20-Poly1305 for payload, and standardized AES-KW for wrapping DEK under the KEK. This removes the KEK nonce registry from the initial schema. AES-KW is provided by OpenSSL; no custom primitive. There is no encrypted desktop offline payload.
3. Local development services bind PostgreSQL 15432 and Redis 56379 because default/reserved Windows ports are unavailable. Production publishes neither.
4. CSRF token remains stable through refresh rotation; it changes on explicit CSRF retrieval. Refresh reuse detection must still recognize the consumed token rather than reject it solely because refresh changed CSRF. Multiple browser tabs synchronize refresh through Web Locks; an uncertain refresh response can require login.
5. Database columns use Prisma camelCase names behind mapped snake_case table names. HTTP contracts remain snake_case for core user/license/application DTOs. Admin event/device records currently expose their explicit storage DTO field names.
6. The development file-based signer rotates with a fail-closed restart window. Zero-downtime staged distribution and a cloud KMS adapter require operational integration; the provider boundary is the local key-store functions. The implementation does not claim transparent cloud-KMS failover.
7. No public password recovery exists without a separately enrolled recovery identity. Admin MFA bootstrap uses an expiring code generated by an operator, never password-only enrollment.

8. Desktop credential entries are namespaced by issuer and product. HTTP responses are capped at 64 KiB while streaming; offline proof parsing is capped separately. The offline clock combines persisted high-water time and a process-local monotonic floor with 30-second tolerance. Online expiry always uses server time. Offline state and clock can still be rolled back by a machine owner or VM snapshot; this is an explicit residual risk, not cryptographic trusted time.
9. The audit worker has no signing-key file or API secrets mounted in production. It holds one outbox row per delivery transaction, uses a bounded timeout and rejects HTTP redirects. Delivery is at-least-once and the sink must deduplicate; local development export is not immutable storage.
10. Current Windows Tauri dependency graph includes unmaintained UNIC crates through tauri-utils/urlpattern. RustSec glib soundness and proc-macro-error maintenance warnings apply to other target graphs, not the Windows build. Cross-platform binaries are not released by this work.
